# 知识图谱与自适应诊断 · 验证版

批次 15（施工单日期 2026-10-22）起提供纯 JS 引擎、原创种子和隔离测试；现已通过 `src/pages/learning/knowledge.vue` 接入只读知识框架页面，并从现有学习 Store 读取已保存收据与事件。宿主为新写作反馈保存节点观察与事先判断核对记录；诊断引擎不直接写掌握结论，未部署生产服务，预测性准确率仍待核对。

## 调研结论与落地范围

据施工单提供的报告摘要，前置诊断回答“先补哪里”，FSRS 回答“什么时候再练”，两者互补；知识关系不能替代真实作答与复习证据。报告数据为未经教师审核的 AI 初稿，不能直接放入产品。原报告全文未随施工单提供，本页不声称复核了全文、题目正确率或学习效果。

本项目将学科按落地顺序分三档，这是实施判断，不是对报告原文的逐字复述：

| 档次       | 范围                     | 诊断方式与准入条件                                                                 |
| ---------- | ------------------------ | ---------------------------------------------------------------------------------- |
| 当前验证档 | 考研英语一/二写作能力    | rubric 为主，少量语法/搭配选择题；只验证引擎，不能当作官方评分或已审核内容         |
| 下一档     | 数学、管综中的可验算任务 | 有明确先修和答案的任务先做自动验算、独立盲解与教师审核；本轮只有测试用数学 fixture |
| 后续评估档 | 申论、其他理科及其他科目 | 先定义教学方法、评分证据与适用关系；理科动画须另验结论，不承诺全科题库             |

许可证边界按客户施工单：`cn-math-taxonomy` 为 上游许可。本轮只采用“显式先修关系 + 自适应诊断 + 质量管线”的通用思路，不读取、复制或改写其代码、节点、边、题目或数据；没有新增第三方组件、依赖或需要公开的派生代码。所有问题、能力标签、关系与引擎均本轮自写，项目现有许可保持。

## 数据与文件

- [引擎](../src/services/learning/knowledge-graph.js)：`validateGraph` 与 `diagnose`，无导入、网络、时钟、随机数、存储或用户事实写入。
- [英语种子](../src/services/learning/knowledge-graph-seed.js)：`knowledgeGraphSeed`，26 节点、36 边（29 hard、7 soft）；22 rubric、4 choice。覆盖审题、结构、句式、语法、表达、论证、检查与带写。每节点均自建不同的主测与降阶题。
- [数学 fixture](../tests/fixtures/knowledge-graph-math.js)：9 节点、8 边，仅供回溯/剪枝测试，不导出到产品种子。
- [单测](../tests/unit/knowledge-graph.spec.js)：结构、状态、回溯、共享先修、拓扑、rubric、种子完整性与输入不变性。

```js
graph = { version: 'version-string', subject: 'subject-id', topics: [], edges: [] };
topic = {
  id,
  subject,
  name,
  type: 'conceptual', // 另可 procedural | reasoning | application | modeling
  masteryCriteria: ['可检查的掌握条件'],
  chapter: '可选章节',
  diagnostic: {
    prompt: '主测题',
    kind: 'rubric',
    rubric: [{ level: 0, label: '未表现', criteria: ['...'] } /* 还需 level 1、2 */],
    lowered: {/* 可选，同 kind 的不同降阶题，不再嵌套 lowered */}
  }
};
edge = { from: '先修ID', to: '后继ID', strength: 'hard', reason: '可选理由' };
```

choice 使用 `options: string[]` 与零起始 `answerIndex`，不混入 rubric；rubric 必须恰含 0/1/2 三档、每档名称和非空条件，不混入选项与答案索引。`lowered` 是验证版的可选扩展，种子全部提供；缺少时引擎返回 `requiresQuestion: true`，由上层先把合格降阶题补入当前图版本，再提交第二答；未提供降阶题却提交第二答将拒绝，绝不复用主测答案或把重复主测冒充降阶题。

校验覆盖非空版本/科目、合法节点类型、唯一非空 ID、掌握条件、题目形状、边引用、hard/soft、无自环、无重复边（同一有向关系也不能同时 hard 与 soft）。hard 子图必须无环；soft 不参与拓扑，可形成提示关系环。失败抛带 `code = 'GRAPH_INVALID'` 的异常，禁止带病执行。

hard 表示本验证任务假设必要的先修，soft 表示有帮助的关系；这两者均是待审核的教学假设，不能声称已证明因果关系。关系方向为先修 → 后继，与诊断从目标向先修的回溯方向相反。

## 纯函数输入与状态机

```js
const result = diagnose(knowledgeGraphSeed, {
  targetId: 'application',
  answers: { application: [0, 0], opening: [2] },
  masteredIds: [] // 可选：调用者已独立核实的先前掌握证据
});
```

`answers` 按节点 ID 映射到至多两项数组，顺序固定为主测、降阶。choice 数字是用户所选的零起始选项索引；rubric 数字是已核对的 0–2 档等级，不是总分、概率或官方考试分。引擎不评阅自由文本，也不调用模型。`null`/缺项表示没有证据；不接受字符串、布尔值、越界分数、稀疏数组、未知节点和第三次作答，非法请求抛 `DIAGNOSIS_INVALID`。需要再次诊断时，上层建立新版本绑定的诊断轮次，不截取历史中的任意两条。

先从目标主测，根据证据决定是否继续；不因传入了某个 soft 节点的答案就访问它。

| 证据                                                              | 本点状态   | 后续                                    |
| ----------------------------------------------------------------- | ---------- | --------------------------------------- |
| 无主测/未答                                                       | `untested` | 请求主测，不探查先修                    |
| 主测 choice 正确 / rubric 2                                       | `mastered` | 剪枝全部 hard 先修；soft 仅提示         |
| 主测 choice 错误 / rubric 0 或 1，降阶未答                        | `untested` | 先出同点降阶题；一次失败不判薄弱        |
| 两次 choice 都错 / rubric 连续 0、0                               | `weak`     | 沿每条 hard 边回溯，重复同样规则        |
| 一对一错（含已提供的正确→错误历史）/ rubric 一次 2、另一次 0 或 1 | `unstable` | 暂停深追，不剪枝；建议本点巩固          |
| 两次 choice 都对 / rubric 2、2                                    | `mastered` | 剪枝 hard 先修                          |
| rubric 0、1 / 1、0 / 1、1                                         | `untested` | 证据不足，不回溯、不硬判 weak，待新证据 |

正常交互在第一次正确后立即结束本点，不额外索取第二题；若调用者已有两次相反证据，则保留 `unstable`，避免只挑正确记录。rubric 的 1 表示部分表现，虽未掌握，也不能与 0 等同来制造“双错根因”。

先前已核实的 `masteredIds` 可跳过本点与其 hard 先修；本轮非空作答优先于旧掌握声明，包括新的部分得分。没有访问的作答不被当作本轮诊断证据。输入图与答案不变，重复调用得到相同结果；返回数组/对象也不持有可变输入引用。

## 输出解释

- `statuses`：全图四态。未访问与被剪枝节点通常保持 `untested`，不会被批量写成 `mastered`；只有显式旧证据可保留原掌握状态。
- `visitedIds` / `evidence`：实际诊断访问范围及采用的分档证据，`source` 区分本轮答案与已有证据；访问不等于已作答。
- `prunedIds`：未访问、由本轮掌握节点剪枝的 hard 先修；同一先修若被其他薄弱分支访问，其真实证据优先，不再列为剪枝。
- `nextTests`：当前主测/降阶待办，携带可展示的 prompt/kind/options。不会返回 choice 正解或 rubric，避免提交前泄题。多分支可并列待办，不要求同时展示。
- `insufficientEvidence`：两次部分表现仍不能下结论的节点；不会伪造第三题。
- `rootCauses`：当前观察到的最深薄弱点候选（ID、`provisional`、未解决 `blockers`）；hard 先修仍未测/不稳时为暂定。已掌握分支处停止检查更远先修。该列表是基于图假设的候选，不是因果证明。
- `learningPath`：已访问且非掌握节点，按 hard DAG 拓扑序排列（先修在前）。包含待测前沿及 unstable，不包括剪枝节点、soft 独立节点、尚未探索的更远先修；完整前沿要随下一次 `diagnose` 重算。
- `softHints`：只返回已访问节点的 soft 关系和理由，不触发回溯、剪枝或掌握推断。
- `complete`：当前规则下无待答题、无证据不足项；不等于用户完成学习，不等于已经掌握，也不证明种子内容已审核。

## 质量管线与已有事实的衔接草案

每个题目与先修关系先过结构校验 → 自动验算（数学/理科；写作做可机械检查，不以字符串规则代替语义评阅）→ 独立盲解（不先看答案、rubric 或首次模型结论）→ 独立参考核对；任何一关未过就不进入真实诊断路径。核对须覆盖主测与降阶、答案唯一性/可接受变式、rubric 边界与 hard 关系；修改后以新版本重新核对。单测验证程序规则，不能替代这些质量关。本种子尚未完成独立盲解与内容核对，仍为验证材料，不另设招募教师或人工测试的前置门槛。

未来适配 [现有学习事实合同](05-DATABASE-SCHEMAS.md) 与 [隐私/费用合同](14-MODEL-PRIVACY-COST.md) 时：

1. 用户明确提交后，沿现有 Service/Store 保存原答与题面快照；绑定账户、会话、图版本、节点、题目、轮次、主测/降阶、帮助情况与评分证据。不推断未答事实，不迁移旧题/旧统计。
2. 自由写作先经已有原答引用/评分校验，再适配到 0–2 分档；AI 评估保持待核对/AI 标注，不因引擎返回 `mastered` 就把它升级为可靠事实。`masteredIds` 不能由模型自述或被剪枝节点生成。
3. 诊断建议路径交给现有教学方法定义与每日编排器；用户看到并选择训练后，复用逐段带写卡与单一输入框，不新增平行教学引擎。
4. FSRS 继续调度具体句式/搭配/练习卡的真实复习记录；诊断 0–2 不能直接映射为现有 1–4 复习 rating，不创建虚构复习，不从节点/剪枝直接改 due、难度或稳定度。`coach.review` 当前使用明确评分和 self_report 来源，这一合同不变。
